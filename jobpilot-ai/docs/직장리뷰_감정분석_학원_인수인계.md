학원 PC에서도 현재 구현된 가상 채용공고, 회사 리뷰, KOTE 감정분석, 커뮤니티

- 가상기업 100곳과 기존 `job_postings` 형식의 가상공고 100건

- 사용자의 리뷰 작성, 좋아요, 신고, 수정, 삭제
- 기업회원의 본인 소유 공고 리뷰·감정 통계 조회
- 홈 화면의 평가 우수 회사/공고 TOP 10
- 자유게시판/Q&A와 관리자용 홈페이지 피드백 감정 통계
- KOTE 5만 건으로 학습한 44감정 TF-IDF/Logistic Regression 기준 모델
- 직장 도메인 검수 후보 240문장 생성기

직장 후보 240문장은 아직 `UNVERIFIED`다. 현재 운영 모델은 KOTE 기준 모델이며,

개선됐다고 발표하면 안 된다.

```powershell
cd jobpilot-ai/ai-server
```

```powershell
  --output ml/sentiment/data/workplace/workplace-candidates-v1.jsonl
```

생성 결과:

```text
POSITIVE  60
NEUTRAL   60
NEGATIVE  60
MIXED     60
합계      240
```

JSONL 예시:

```json
{
  "id": "WP-01-1-MIX",
  "text": "개발팀에서 근무하는 동안 평소 업무량은 적당했지만 장애가 발생한 주에는 며칠씩 야근했습니다.",
  "overall": "MIXED",
  "aspects": {"WORKLOAD": "MIXED"},
  "source_type": "SYNTHETIC_CURATED",
  "review_status": "UNVERIFIED",
  "template_group": "CASE-01"
}
```

검수 절차:

1. 최소 2명이 문장만 보고 독립적으로 라벨링한다.
2. 전체 감정과 평가 항목을 각각 확인한다.
3. 불일치는 근거를 기록하고 합의한다.
4. 검수 완료 행만 `VERIFIED`로 바꾼다.
5. 같은 `template_group`은 동일 split에 넣는다.
6. 검수 전 데이터로 최종 성능을 발표하지 않는다.

현재 코드는 `UNVERIFIED` 행이 최종 평가에 들어가면 실패하도록 되어 있다.

## 13. 리뷰 감정분석 처리 흐름

```text
사용자 리뷰 작성
  → company_reviews에 PENDING 저장
  → ReviewAnalysisWorker가 10초 간격으로 선점
  → Spring SentimentAiClient가 FastAPI 내부 API 호출
  → 44개 감정과 표시용 극성 계산
  → company_review_analyses 저장
  → 공고 상세에서 공개 리뷰 전체 평균 집계
```

커뮤니티는 사용자가 `홈페이지 기능·사용 경험 피드백`을 체크한 게시글만 분석한다.
일반 자유게시판 대화는 `SKIPPED`이며 회사 리뷰 통계와 섞이지 않는다.

## 14. DB 확인 쿼리

```sql
SELECT COUNT(*)
FROM job_postings
WHERE source_provider = 'FICTIONAL_DEMO';

SELECT COUNT(*)
FROM company_reviews
WHERE source_type = 'SYNTHETIC_DEMO';

SELECT COUNT(*)
FROM job_requirements r
JOIN job_postings p ON p.id = r.job_posting_id
WHERE p.source_provider = 'FICTIONAL_DEMO';

SELECT p.id, p.company_name, p.title, p.salary, COUNT(r.id) AS review_count
FROM job_postings p
LEFT JOIN company_reviews r ON r.job_posting_id = p.id
WHERE p.source_provider = 'FICTIONAL_DEMO'
GROUP BY p.id, p.company_name, p.title, p.salary
ORDER BY p.id
LIMIT 10;
```

정상 기대값:

```text
가상공고 100
합성리뷰 500
요구사항 700 이상
공고당 리뷰 5
```

## 16. CI/CD 및 운영 배포

`.github/workflows/ci.yml`은 `main`과 `김한영브뤤취학원` 푸시를 검사한다.
`.github/workflows/deploy.yml`은 `main` 푸시에만 운영 배포를 실행한다.

배포 전 필수:

```powershell
cd jobpilot-ai/frontend
npm run build

cd ../backend
mvn test

cd ../ai-server
.\.venv\Scripts\python.exe -m pytest `
  tests/test_sentiment_dataset.py `
  tests/test_sentiment_labels.py `
  tests/test_sentiment_training.py `
  tests/test_router_sentiment.py `
  tests/test_workplace_dataset.py `
  -q -p no:cacheprovider
```

원격 main이 작업 브랜치의 직전 커밋이고 충돌이 없는지 확인한다.

```powershell
git fetch origin
git rev-list --left-right --count origin/main...HEAD
```

출력이 `0  N`이면 main에 없는 작업 커밋만 N개 있다는 뜻이다. 검증 후:

```powershell
git push origin HEAD:refs/heads/main
```

이 푸시는 운영 배포를 발생시키므로 팀 승인 없이 실행하지 않는다. Flyway migration은
main 배포에서만 적용한다.

## 18. 자주 생기는 문제

### 가상기업이 생성되지 않음

- `APP_REVIEW_DEMO_SEED_ENABLED=true` 확인
- Flyway V43~V45 적용 확인
- `portfolio_demo_dataset_versions`의 버전 확인
- 백엔드 시작 로그에서 cardinality mismatch 확인

### 리뷰가 계속 PENDING

- AI 서버 `/sentiment/health`가 `READY`인지 확인
- `INTERNAL_API_KEY`가 백엔드와 AI 서버에서 동일한지 확인
- `APP_SENTIMENT_WORKER_ENABLED=true` 확인
- 백엔드에서 AI 서버 주소가 `http://ai-server:8001`인지 확인

### 홈 TOP 10이 비어 있음

- 순위 API가 비로그인 상태에서 HTTP 200인지 확인
- 분석 완료 리뷰가 있는지 확인
- 공고당 공개 리뷰가 5건 이상인지 확인

### Maven이 실행되지 않음

- Java 21과 `JAVA_HOME` 확인
- IntelliJ 내장 Maven 사용
- Maven 로컬 캐시 접근 권한 확인

### 배포 직후 일시적인 502

백엔드 컨테이너 교체 중 잠깐 발생할 수 있다. 2분 이상 지속되면 GitHub Actions와
백엔드 컨테이너 로그를 확인한다.
