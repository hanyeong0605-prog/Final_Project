# 모의면접 · 실전면접 (포트폴리오 정리)

> 이 문서는 면접·발표에서 "무엇을 왜 그렇게 만들었는지" 설명하기 위한 요약이다.
> 구현 세부는 [mock-interview-tech-reference.md](./mock-interview-tech-reference.md) 참고.

## 한 줄 요약

취업 준비생이 실제 화상면접과 같은 흐름으로 연습하고, 답변 내용뿐 아니라 말투와 화면 앞에서의
행동까지 근거 있는 수치로 돌려받는 기능. 2026-08-29에 **무료 모의면접**과 **구독자 실전면접**을
분리하고, 카메라 지표를 기준 자세 보정 위에서 다시 설계했다.

## 왜 두 모드로 나눴나

Gemini 호출은 사용자 한 명의 세션마다 질문 수만큼 발생한다. 모든 사용자에게 실시간 생성을 열어두면
비용이 사용자 수에 그대로 비례하는데, 무료 사용자가 얻는 가치는 "면접 흐름을 연습해본다"에 가깝고
그건 이미 검수된 질문 코퍼스로 충분했다. 그래서

- **무료**: 로컬 코퍼스에서 순차로 뽑는다. 순차라서 지금까지 나온 질문을 매번 제외할 수 있어
  세션 안 중복이 원천 차단된다.
- **실전**: 회원 스펙과 채용공고를 근거로 Gemini가 질문을 만든다.

로 나눴다. 중요한 건 **이 구분을 프론트가 아니라 서버가 보장한다**는 점이다. 서버 핸들러 맨 앞에서
무료 요청을 코퍼스로 반환해버리므로, 프론트가 어떤 값을 보내도 무료 요청이 유료 경로에 도달할 수 없다.
`mode` 필드가 없을 때의 기본값도 무료다 - 필드가 빠졌다고 비용이 나가는 쪽으로 기울면 안 된다.

## 설계에서 가장 신경 쓴 것: "모르는 것을 아는 척하지 않기"

### 스펙에 없으면 없다고 단정하지 않는다

`스펙 + 회사` 근거에서는 공고 요구사항과 회원 스펙을 키워드로 대조한다. 이때 일치하지 않는 항목을
"이 지원자에게는 없는 역량"으로 넘기면, Gemini는 그걸 사실로 전제한 압박 질문을 만든다.
그래서 대조 결과를 `보유 근거 확인` / `스펙에서 확인되지 않음` 두 가지로만 표기하고,
후자를 단정하거나 추궁하지 말라는 규칙을 프롬프트에 함께 건다.

같은 이유로 한 글자 키워드(`C`, `R`)는 대조에서 제외했다. 진짜 기술명을 놓치는 손해보다,
한글 한 글자가 요구사항 문장 아무 데나 걸려 "보유 확인"으로 잘못 표시되는 쪽이 더 위험하다.

### 카메라로 심리를 판독하지 않는다

표정으로 긴장도나 자신감을 점수 매기는 기능은 만들지 않았다. 카메라로 알 수 있는 건
"고개가 얼마나 움직였나", "카메라를 얼마나 봤나", "얼굴이 화면 안에 있었나" 같은 관찰 가능한 행동뿐이고,
그걸 심리 상태로 번역하는 순간 근거 없는 판정이 된다. 리포트 문구도 관찰과 연습 방법만 다룬다.

### 기준이 없는 수치는 보여주지 않는다

카메라 높이와 평소 자세는 사람마다 다르다. 예전 구현은 코끝의 2D 이동량 하나로 "고개 움직임"을
만들었는데, 노트북을 옆에 두고 쓰는 사람은 가만히 있어도 값이 크게 나왔다. 지금은 기기 점검 단계에서
그 사람의 정면 자세를 2~3초 보정한 뒤, **그 기준 대비** 얼마나 벗어났는지를 잰다.

보정에 실패했거나, 답변이 너무 짧거나, 얼굴이 잡힌 프레임이 적으면 신뢰도를 `데이터 부족`으로 두고
**수치를 화면에 아예 표시하지 않는다**. 근거로 쓸 수 없는 숫자를 띄워두면 사용자는 그걸 근거로 받아들인다.

## 사용자 흐름

1. `모의면접 / 실전면접`을 세그먼트로 고른다. 비구독자가 실전을 고르면 설정값을 바꾸지 않고
   구독 안내만 띄운다. 구독 상태 확인이 끝나기 전에는 실전을 고를 수 없다 - 확인 중과 "비구독 확정"을
   구분하지 않으면 구독자에게 잠깐 구독 안내가 뜬다.
2. 고른 모드에 필요한 설정만 단계적으로 보여준다(무료: 질문 유형·분야 / 실전: 질문 근거·공고).
3. 질문 수를 `− [입력] +`로 정한다. 범위 밖 값, 소수, 빈 입력은 확정 시점에 보정한다.
4. 카메라·마이크 또는 채팅으로 진행한다. 모든 질문에서 건너뛸 수 있고, 건너뛴 질문은 종합 평가에서
   미응답으로 처리된다.
5. 질문별 지표를 먼저 보고, `AI 분석 보기`를 눌렀을 때만 Gemini 종합 평가를 한 번 호출한다.

## 접근성 관련 결정

세그먼트와 칩은 보기엔 버튼 묶음이지만 마크업은 `fieldset` + `legend` + 진짜 `radio` 입력이다.
버튼으로 만들면 키보드 화살표 이동과 스크린리더의 "2개 중 1번째" 안내가 사라진다.
라디오 자체는 시각적으로 숨겨져 있으므로 포커스 링은 라벨에 그린다.
질문 수 안내("최대 5개까지 선택할 수 있어요")는 `aria-describedby`로 입력창에 묶여 있다.

## 개편 중 실제로 잡은 버그

- **답변이 한 질문씩 밀려 저장되던 문제**: `setSessionAnswers` 업데이터 *안에서* 현재 질문 ref를
  읽고 있었는데, 업데이터는 다음 렌더에서 실행되고 그 사이에 ref가 다음 질문으로 바뀐다.
  채팅 모드에서 질문 3개를 건너뛰면 자기소개 답변이 사라지고 마지막 질문이 두 번 저장됐다.
- **질문 수 +/- 연타가 한 번만 먹던 문제**: 컴포넌트로 분리하면서 `value` prop을 읽어 계산하게 됐는데,
  같은 렌더 안에서 연속으로 누르면 전부 같은 값을 읽는다. 함수형 업데이트로 되돌렸다.
