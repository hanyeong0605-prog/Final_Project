# 작업 전/후 git 순서 (내 작업물 안 날리고, 팀원 것 안 망가뜨리기)

## 작업 시작 전

```
git status
git pull origin main
```

`git status`가 지저분하면(커밋 안 한 게 남아있으면) 먼저 아래 "작업 끝난 후" 순서부터
밟고 나서 pull 하기 - 커밋 안 된 상태로 pull 받으면 충돌 위험이 커진다.

## 작업 끝난 후 (매번 이 순서 그대로)

```
git add -A
git commit -m "무슨 작업했는지 한 줄로"
git pull origin main
git push
```

**포인트 하나하나**:

1. **커밋을 항상 먼저 한다.** pull보다 먼저 커밋해두면, pull이 뭘 가져오든 내 작업은
   이미 커밋 안에 안전하게 들어있어서 절대 안 없어진다. (커밋 안 된 상태에서 pull 받다가
   충돌 나면 훨씬 골치 아파짐)
2. **커밋 메시지는 반드시 `-m "..."`로 같이 써서 넣는다.** `-m` 없이 `git commit`만 치면
   메모장/vim 같은 편집기가 열리는데, 이 창을 제대로 안 닫고 나가면(`:wq`로 저장 안 하고
   그냥 터미널을 닫아버리는 등) `.git/index.lock` 파일이 안 지워진 채로 남아서, 이후
   모든 git 명령이 "다른 git 프로세스가 실행 중"이라며 계속 막힌다 - 이번에 실제로
   겪었던 문제. `-m`을 쓰면 편집기 자체가 안 열려서 이 문제가 원천적으로 안 생긴다.
3. **push 전에 pull을 한 번 더 한다.** 커밋한 사이에 팀원이 먼저 push했을 수도 있어서,
   바로 push하면 거부당할 수 있다. pull로 먼저 최신 상태를 받아서 병합한 뒤 push하면
   안전하다.

## 만약 `.git/index.lock: File exists` 에러가 나면

```
rm /d/Final_Project/.git/index.lock
```

그 다음 위 순서(add -> commit -m -> pull -> push)를 다시 하면 된다. 이 파일은 git이
작업 중 임시로 만들었다가 정상적으로 끝나면 자동으로 지워지는 파일인데, 중간에 편집기가
안 닫히는 등으로 작업이 끊기면 안 지워진 채로 남는다 - 새로 계속 생기는 게 아니라
한 번 생긴 게 안 지워져서 계속 막히는 것이므로, 지우고 나면(그리고 앞으로 `-m`을 계속
쓰면) 다시 안 생긴다.

## 병합 충돌(conflict)이 나면

`git pull` 도중 "CONFLICT"라는 메시지가 뜨면, 같은 파일의 같은 부분을 나와 팀원이
동시에 고친 경우다. 데이터가 없어지는 게 아니라 git이 판단을 못 해서 사람이 골라야
하는 상황일 뿐이니 당황하지 말고, 충돌 난 파일을 열어서 `<<<<<<<` / `=======` /
`>>>>>>>` 표시된 부분을 보고 어느 쪽을 남길지 정리한 다음 다시
`git add -A && git commit -m "충돌 해결"`로 마무리하면 된다.
