# 회사 리뷰·커뮤니티 감정분석 구현 결과

브랜치: `김한영브뤤취학원`

## 완료 범위

- KOTE 공개 데이터 50,000건을 고정 커밋에서 내려받아 40,000/5,000/5,000으로 분리하고,
  44개 감정 다중 라벨 기준 모델을 직접 학습·평가했다.
- 모델 artifact, 라벨 정책, 모델 카드, 재학습·평가·데이터 검증 스크립트를 저장소와
  AI Docker 이미지에 포함했다. 내부 키 인증 단건/배치 추론 API와 상태 API를 제공한다.
- 실제 회사와 섞이지 않는 `FICTIONAL_DEMO` 회사 100곳, 공고 100건, 합성 리뷰 500건을
  멱등적으로 생성한다. 이름과 화면에 가상 데이터임을 명시한다.
- 로그인 사용자는 리뷰 작성·수정·삭제·좋아요·신고와 분석 결과 조회를 할 수 있다.
  기업회원은 본인이 등록한 공고의 리뷰·평점·감정 요약만 조회할 수 있다.
- 홈 화면 TOP 10은 최소 리뷰 5건인 가상 데이터만 대상으로 베이지안 평점, 긍정 신호,
  리뷰 수, 최신성을 조합한다. 감정 점수를 확률이나 사실 판정으로 표시하지 않는다.
- 자유게시판/Q&A에 검색·정렬·조회수·좋아요·댓글·한 단계 답글·수정·삭제·신고·비공개
  문의를 구현했다. 작성자가 `서비스 피드백`으로 표시한 글만 별도 감정 큐에 들어간다.
- 관리자 화면은 서비스 피드백 감정 통계·최근 글 미리보기와 게시글 숨김/복원/삭제,
  신고 리뷰 숨김/복원/삭제/재분석을 제공한다. 회사 리뷰 통계와 게시판 통계는 분리된다.
- 분석 worker는 트랜잭션 밖 추론, lease, 지연 재시도, 최대 시도, 원문 해시 검증으로
  수정 전의 늦은 응답이 최신 결과를 덮지 못하게 한다.
- Flyway V43/V44, JPA 검증, Docker/CI 모델 포함 확인, AI → backend → frontend 배포 순서를 반영했다.

## 검증 결과

- Java 21 백엔드: 81개 통과, 실패 0. 기본 실행에서는 외부 MySQL 통합 테스트 9개 제외.
- 별도 MySQL 8 통합 검증: V1~V44 전체 마이그레이션, Hibernate validate, 애플리케이션
  health, 회사 100/공고 100/리뷰 500 exact count, 작업 큐와 커뮤니티 권한 시나리오 통과.
- AI: 191개 통과. Windows에서 열린 `NamedTemporaryFile`을 ffmpeg가 덮어쓰지 못하는
  기존 오디오 통합 테스트 1개만 실행 환경상 제외되며 감정분석 테스트는 모두 통과했다.
- 프론트: Vitest 42개 통과, TypeScript와 Vite production build 통과.
- 운영 npm 의존성: high/critical 0. React Router 6 계열 전체에 남은 moderate 2건은
  7.x 메이저 전환이 필요하다. 현재 앱은 SSR hydration을 사용하지 않고 사용자 입력 URL로
  navigate하지 않으므로 직접 노출은 제한적이며, 강제 메이저 업그레이드는 이번 기능에서 제외했다.

## 운영 설정

- `APP_REVIEW_DEMO_SEED_ENABLED=true`면 가상 시연 데이터가 없을 때만 생성된다.
- `APP_REVIEW_DEMO_EMPLOYER_ID`는 승인된 시연 기업회원 ID를 운영자가 지정할 때만 사용한다.
  기본값 0은 실제 계정을 임의로 연결하지 않는다.
- `APP_SENTIMENT_WORKER_ENABLED=true`로 리뷰/피드백 분석 worker를 활성화한다.
- 모델은 자동 제재나 허위사실 판단에 사용하지 않으며 참고용 경향으로만 노출한다.
