# 감정분석 기반 가상기업 리뷰·커뮤니티 설계

작성일: 2026-08-29  
대상 브랜치: `김한영브뤤취학원`

## 1. 목적

JobPilot에 실제 공개 한국어 감정 데이터로 직접 학습한 모델을 추가하고, 그 모델을 가상기업·가상 채용공고 리뷰와 커뮤니티 게시글에 적용한다. 두 적용 영역은 목적과 노출 대상을 분리한다. 회사·공고 리뷰 분석은 구직자와 해당 기업회원에게 채용 평가를 제공하고, 커뮤니티 분석은 자유게시판·문의게시판에서 나타난 서비스에 대한 사용자 반응을 관리자가 미리보기와 통계로 확인하는 운영 기능이다. 홈 화면에는 신뢰도 보정 평가를 이용한 기업·공고 TOP 10을 제공한다.

이 기능은 다음 세 종류의 데이터를 명확히 분리한다.

- `PUBLIC_RESEARCH`: 외부 공개 연구 데이터. 모델의 기본 감정 학습에 사용한다.
- `HUMAN_VALIDATED_DOMAIN`: 직장·채용 도메인 문장을 사람이 검수한 데이터. 도메인 보정과 최종 평가에 사용한다.
- `SYNTHETIC_DEMO`: 가상 회사·공고·리뷰·게시글. 서비스 시연과 추론 적용에 사용하며 실제 데이터라고 표현하지 않는다.

## 2. 범위와 단계

### 2.1 1차 제공 범위

- KOTE 원본 데이터 다운로드·무결성 검증·출처 기록
- KOTE 43개 감정 및 `감정 없음` 다중 라벨 기준 모델 학습
- 학습·검증·테스트 및 재현 가능한 평가 보고서
- FastAPI 감정 추론 API
- 가상기업 100개와 기업별 가상공고 1개, 총 100개
- 회사별 초기 리뷰 5개, 총 500개
- 회사 필수, 관련 공고 선택 방식의 신규 리뷰 CRUD
- 별점, 좋아요, 신고, 관리자 숨김·복원·삭제
- 회사·공고 상세의 감정 요약
- 기업회원의 본인 공고 리뷰 분석 대시보드
- 홈 화면 회사 TOP 10·공고 TOP 10

### 2.2 후속 제공 범위

- 자유게시판과 문의게시판
- 게시글·댓글 CRUD, 조회수, 좋아요, 신고, 비공개 문의
- 관리자 전용 커뮤니티 감정 미리보기·기간별 통계·게시판별 추세
- 서비스 평가성 게시글과 일반 대화의 구분
- 직장·채용 도메인 라벨 검수 화면과 재학습 관리
- 급여·복지, 워라밸, 조직문화, 성장성, 경영진의 항목별 감정분석

초기 구현은 전체 감정 모델과 리뷰 서비스의 완결성을 우선한다. 항목별 감정은 사람이 검수한 항목 라벨이 확보된 후 확장한다.

## 3. 데이터 출처와 책임

### 3.1 KOTE

KOTE(Korean Online That-gul Emotions)는 서울대학교 심리학과 및 인지과학 협동과정 연구진이 구축하고 LREC-COLING 2024에 발표한 공개 한국어 감정 데이터셋이다.

- 공식 저장소: `https://github.com/searle-j/KOTE`
- 논문: `https://aclanthology.org/2024.lrec-main.1499/`
- 규모: 한국어 온라인 댓글 50,000건
- 라벨: 43개 감정과 `감정 없음`
- 원본 분할: 학습 40,000 / 검증 5,000 / 테스트 5,000
- 라벨링: 댓글별 5명의 크라우드소싱 평가
- 저장소 라이선스: MIT

다운로드 스크립트는 원본 URL, 다운로드 시각, Git 커밋 해시, 파일 SHA-256, 행 수를 manifest에 기록한다. 원본 데이터는 Git과 Docker 빌드 컨텍스트에서 제외한다. 데이터 자체가 아니라 다운로드·검증·전처리·학습 코드와 출처 문서를 버전 관리한다.

### 3.2 가상 데이터

가상기업과 공고는 현재 크롤링 공고의 필드 구조와 일반적인 채용 문체만 참고하고 실제 기업명·로고·고유 문구·본문을 복제하지 않는다.

- 회사명에 `(가상기업)` 표기
- DB의 `source_type`을 `FICTIONAL_DEMO`로 저장
- 목록과 상세 화면에 `포트폴리오 시연용 가상 공고` 배지 표시
- 상세 화면에 실제 기업과 무관하다는 고정 안내 표시
- 실제 크롤링 공고에는 리뷰 작성 기능을 노출하지 않음

가상 리뷰에는 `SYNTHETIC_DEMO` 출처를 저장한다. 회사별 리뷰 5개는 해당 회사의 단일 가상공고에도 연결해 회사·공고 TOP 10을 모두 시연할 수 있게 한다. 합성 리뷰는 화면 시연과 추론 대상으로 사용하며, 별도 사람 검수 없이 모델의 정답 학습 데이터로 사용하지 않는다.

### 3.3 사람 검수 데이터

직장·채용 도메인 보정을 위해 합성한 후보 문장에는 초벌 라벨을 붙일 수 있으나, 검수자가 확정한 문장만 `HUMAN_VALIDATED_DOMAIN`으로 승격한다. 특히 최종 테스트 세트는 전수 사람 검수를 원칙으로 한다. 신규 사용자 리뷰도 자동으로 학습 정답이 되지 않으며 관리자 검수 후에만 재학습 후보가 된다.

## 4. 감정 모델 설계

### 4.1 모델 출력

KOTE 원본 의미를 보존하기 위해 44개 출력의 다중 라벨 분류를 기본으로 한다. 하나의 문장은 여러 감정을 동시에 가질 수 있다.

```json
{
  "modelVersion": "kote-baseline-2026-08-29.1",
  "emotions": [
    {"label": "기대감", "score": 0.82},
    {"label": "불안/걱정", "score": 0.47}
  ],
  "polarity": {
    "label": "MIXED",
    "positive": 0.58,
    "neutral": 0.06,
    "negative": 0.36
  }
}
```

긍정·중립·부정은 원본 정답 라벨인 것처럼 주장하지 않는다. 버전 관리되는 감정-극성 매핑표를 사용해 서비스 표시용으로 집계하고, 긍정과 부정이 동시에 강하면 `MIXED`로 표시한다. 매핑 근거와 예외는 별도 데이터 문서에 기록한다.

### 4.2 학습 파이프라인

1. 공식 저장소에서 KOTE를 다운로드한다.
2. manifest와 체크섬으로 원본을 검증한다.
3. 인코딩, 빈 문장, 중복, 라벨 범위를 검사한다.
4. KOTE 공식 train/validation/test 분할을 유지한다.
5. TF-IDF 기반 One-vs-Rest Logistic Regression을 기준 모델로 학습한다.
6. KcELECTRA 계열 다중 라벨 파인튜닝을 개선 모델로 학습한다.
7. Micro/Macro-F1, 라벨별 Precision/Recall, 임계값, 추론 시간을 비교한다.
8. 개선 모델이 기준 모델보다 검증·테스트 지표와 운영 조건에서 우수할 때만 채택한다.
9. 모델, 라벨 순서, 전처리 설정, 임계값, 평가 지표를 하나의 버전 단위로 저장한다.

Transformer 학습은 로컬 GPU 또는 Colab에서 수행하고 운영 EC2는 저장된 모델의 CPU 추론만 담당한다. 모델 로딩 실패 시 AI 서버 전체가 죽지 않도록 감정 도메인만 `UNAVAILABLE` 상태를 반환한다.

### 4.3 서비스 추론

리뷰 저장은 감정 서버 성공 여부와 분리한다.

```text
리뷰 저장 → 분석 작업 PENDING → FastAPI 호출
         → 성공: COMPLETED + 결과 저장
         → 실패: FAILED + 오류 코드 저장 → 재시도
```

사용자 요청 시간 안에 분석이 끝나면 즉시 결과를 표시하고, 시간 초과 시 리뷰는 정상 저장한 뒤 비동기 재분석한다. 동일 본문과 동일 모델 버전은 콘텐츠 해시를 사용해 중복 추론을 피한다.

## 5. 도메인과 데이터 모델

### 5.1 회사·공고

기존 공고와의 호환성을 우선하되 다음 개념을 명시한다.

- 회사 식별자와 표시명
- `source_type`: `CRAWLED`, `EMPLOYER_CREATED`, `FICTIONAL_DEMO`
- 기업회원 소유 관계
- 리뷰 허용 여부

가상기업 시연 계정은 특정 가상회사와 연결한다. 기업회원이 작성한 공고는 기업회원 소유 관계를 통해 접근 권한을 판정한다.

### 5.2 리뷰

리뷰는 회사에 반드시 귀속되고 관련 공고는 선택적으로 연결한다.

- `company_id`: 필수
- `job_posting_id`: 선택
- `author_member_id`: 필수
- 총 별점과 선택적 항목별 별점
- 장점, 단점, 한줄평
- 작성·수정 시각
- 공개, 숨김, 삭제 상태
- 데이터 출처
- 감정분석 상태와 최신 모델 버전

일반 사용자는 회사별 리뷰 1개를 원칙으로 하며 수정·삭제할 수 있다. 리뷰 수정 시 기존 감정 결과를 보존 이력으로 남기고 새 버전으로 재분석한다.

### 5.3 분석 결과

분석 결과는 리뷰 본문과 분리해 모델 재배포와 재분석을 지원한다.

- 대상 유형과 대상 ID
- 모델 버전
- 콘텐츠 해시
- 세부 감정별 점수
- 집계 극성 및 점수
- 분석 상태, 분석 시각, 실패 코드
- 활성 결과 여부

## 6. 권한과 운영 정책

### 6.1 일반회원

- 가상기업 리뷰 조회
- 로그인 후 리뷰 작성
- 본인 리뷰 수정·삭제
- 리뷰 좋아요·신고
- 다른 작성자의 개인정보는 조회 불가

### 6.2 기업회원

- 본인 소유 공고에 연결된 리뷰 조회
- 본인 회사 전체와 공고별 감정 통계 조회
- 기간별 변화와 주요 감정 조회
- 부적절한 리뷰 또는 분석 오류 신고
- 다른 기업 소유 공고의 비공개 분석 조회 불가
- 리뷰 수정·삭제 및 감정 결과 변경 불가

공고 ID를 조작해도 다른 기업 데이터가 노출되지 않도록 모든 기업 API에서 Spring 백엔드가 소유권을 검증한다.

### 6.3 관리자

- 신고 검토
- 리뷰 숨김·복원·삭제
- 분석 재시도
- 가상 데이터 재생성 상태 확인
- 검수 라벨 승인과 재학습 후보 관리

관리 작업은 사유와 수행자를 감사 로그에 기록한다.

## 7. 기업회원 분석 대시보드

기업회원 대시보드에는 `공고 리뷰 분석` 메뉴를 제공한다.

- 공고별 리뷰 수와 평균 별점
- 별점 분포
- 긍정·중립·부정·복합 감정 비율
- 주요 세부 감정
- 기간별 감정 변화
- 신규 리뷰 수
- 리뷰 원문과 분석 결과
- 분석 대기·실패 상태
- 부정 감정 급증 안내
- 여러 소유 공고 간 비교

데이터가 적으면 수치를 과신하지 않도록 표본 부족 안내를 표시한다. 감정분석은 사용자 의견을 요약한 참고 자료이며 기업의 객관적 품질 판정으로 표현하지 않는다.

## 8. 홈 화면 TOP 10

홈 화면에는 두 개의 탭을 제공한다.

- `평가가 좋은 회사 TOP 10`
- `평가가 좋은 공고 TOP 10`

단순 평균 별점 대신 신뢰도 보정 점수를 사용한다.

```text
ranking_score =
  bayesian_rating * 0.60
  + positive_sentiment * 0.25
  + review_volume_confidence * 0.10
  + recency_score * 0.05
```

초기 가중치는 위 값으로 시작하되 실제 시드 데이터 분포를 검증한 후 문서화된 버전으로 확정한다.

- 공개 리뷰가 최소 5개인 대상만 후보로 한다.
- 완료된 감정분석만 감정 점수에 반영한다.
- 숨김·삭제·신고 검토 중 리뷰는 제외한다.
- 동일 사용자의 중복 평가는 차단한다.
- 동점이면 리뷰 수, 최신 리뷰 시각 순으로 정렬한다.
- 1차 시연에서는 `FICTIONAL_DEMO`만 순위에 포함한다.
- 카드와 상세 화면에 가상 데이터 표시를 유지한다.

문구는 `사용자 리뷰와 감정분석 결과를 바탕으로 산정한 순위`로 제한한다. 감정 점수가 기업의 객관적 우열을 증명한다고 표현하지 않는다.

## 9. 커뮤니티와 관리자용 감정분석

자유게시판과 문의게시판은 공통 게시판 도메인 위에 유형을 분리한다.

- 게시글 작성·조회·수정·삭제
- 목록, 검색, 정렬, 페이징
- 조회수 중복 방지 정책
- 댓글과 1단계 대댓글
- 좋아요와 신고
- 문의글 공개·비공개
- 관리자 숨김·복원·삭제
- 게시글·댓글 감정분석

### 9.1 회사·공고 리뷰 분석과의 분리

동일한 KOTE 기반 추론 엔진을 재사용할 수 있지만 분석 문맥, 집계, 권한, 화면을 분리한다.

| 구분 | 회사·공고 리뷰 분석 | 커뮤니티 감정분석 |
|---|---|---|
| 분석 대상 | 가상기업 리뷰 | 자유게시판·문의게시판의 게시글과 댓글 |
| 목적 | 회사·공고 평가 참고 | JobPilot 서비스에 대한 사용자 반응 파악 |
| 주요 사용자 | 구직자, 해당 기업회원 | 관리자 |
| 집계 기준 | 회사·공고·별점 | 게시판·기간·글 유형 |
| 주요 화면 | 회사 상세, 공고 상세, 기업 대시보드 | 관리자 커뮤니티 감정 대시보드 |
| 순위 반영 | 홈 TOP 10에 반영 | 기업·공고 순위에 절대 반영하지 않음 |

분석 결과에는 `analysis_context`를 저장한다.

- `COMPANY_REVIEW`: 회사·공고 리뷰
- `COMMUNITY_POST`: 게시글 본문
- `COMMUNITY_COMMENT`: 게시글 댓글

서로 다른 문맥의 통계가 섞이지 않도록 Backend 집계 쿼리와 API를 분리한다.

### 9.2 서비스 평가성 콘텐츠 구분

자유게시판의 모든 글이 홈페이지에 대한 평가인 것은 아니다. 따라서 전체 커뮤니티 분위기와 서비스 피드백 통계를 분리한다.

- 문의게시판 글은 기본적으로 서비스 피드백 후보로 취급한다.
- 자유게시판 작성 시 `서비스 후기·건의` 카테고리를 선택할 수 있게 한다.
- 그 외 자유게시판 글은 전체 커뮤니티 감정 통계에는 포함하지만 서비스 만족도 통계에는 포함하지 않는다.
- 감정 모델만으로 글의 주제를 추정해 서비스 평가로 단정하지 않는다.

### 9.3 관리자 감정 대시보드

관리자 페이지에 `커뮤니티 감정` 탭을 추가한다.

- 오늘·최근 7일·최근 30일의 긍정·중립·부정·복합 비율
- 자유게시판·문의게시판별 감정 분포
- `서비스 후기·건의`만 필터링한 서비스 반응 통계
- 이전 기간 대비 긍정·부정 비율 변화
- 자주 나타난 세부 감정
- 최근 부정·복합 게시글 미리보기
- 게시글 제목, 본문 일부, 감정 점수, 작성 시각, 게시판 유형
- 미리보기에서 원문과 댓글 관리 화면으로 이동
- 분석 대기·실패 건수 및 관리자 재분석
- 날짜, 게시판, 감정, 카테고리 필터

비공개 문의글의 내용과 통계는 관리자에게만 제공하며 공개 커뮤니티 통계 API에 포함하지 않는다. 삭제·숨김 처리된 글은 기본 통계에서 제외하되 감사 목적으로 기존 분석 이력은 보존한다.

게시판 감정분석은 사용자에게 글의 옳고 그름을 판정하지 않고, 부정 감정만으로 글을 자동 삭제하거나 제재하지 않는다. 관리자가 사용자 반응을 빠르게 파악하고 원문을 확인할 수 있는 운영 보조 수단이다. 욕설·혐오·위협 탐지는 감정분석과 다른 문제이므로 별도의 안전 분류 모델 없이는 동일 기능이라고 주장하지 않는다.

## 10. API 경계

### 10.1 Spring Backend

- 리뷰·별점·좋아요·신고의 원본 상태를 관리한다.
- 회사·공고·기업회원 소유권을 검증한다.
- 감정분석 결과를 저장하고 집계 API를 제공한다.
- 회사·공고 리뷰 집계와 관리자 커뮤니티 집계를 별도 API로 제공한다.
- 홈 순위 점수를 계산하거나 검증된 집계 결과를 제공한다.
- AI 서버 실패가 리뷰 작성 실패로 전파되지 않게 한다.

### 10.2 FastAPI AI Server

- 모델과 라벨 메타데이터를 로딩한다.
- 단건 및 제한된 배치 감정 추론을 제공한다.
- 학습은 운영 HTTP 요청으로 실행하지 않는다.
- 모델 버전과 준비 상태를 health/metadata API로 제공한다.

예상 내부 API:

- `POST /sentiment/analyze`
- `POST /sentiment/analyze/batch`
- `GET /sentiment/model`
- `GET /sentiment/health`

예상 관리자 Backend API:

- `GET /api/v1/admin/community-sentiment/summary`
- `GET /api/v1/admin/community-sentiment/trends`
- `GET /api/v1/admin/community-sentiment/previews`
- `POST /api/v1/admin/community-sentiment/{targetType}/{targetId}/reanalyze`

## 11. 오류 처리

- AI 서버 시간 초과: 원문 저장 후 `PENDING` 또는 `FAILED` 처리
- 모델 미로딩: 감정 기능만 일시 사용 불가로 표시
- 잘못된 모델 출력: 스키마 검증 실패로 저장하지 않고 재시도 대상화
- 리뷰 수정 경쟁: 낙관적 잠금 또는 갱신 시각 검증
- 삭제된 리뷰의 늦은 분석 응답: 콘텐츠 버전이 다르면 폐기
- 시드 중복 실행: 고정 외부 키와 upsert로 멱등성 보장
- 순위 데이터 부족: 빈 상태 또는 표본 부족 표시

## 14. 완료 기준

- 공식 KOTE 데이터를 재현 가능하게 내려받고 검증할 수 있다.
- 최소 기준 모델을 실제 데이터로 직접 학습하고 저장할 수 있다.
- 보지 않은 테스트 세트의 지표와 오류 사례가 자동 생성된다.
- 사용자가 가상기업 리뷰를 새로 작성하면 저장 후 감정 결과를 확인할 수 있다.
- 기업회원은 본인 공고의 리뷰와 집계만 확인할 수 있다.
- 홈 화면 회사·공고 TOP 10이 신뢰도 보정 규칙으로 표시된다.
- 관리자는 자유·문의게시판에서 나타난 서비스 반응을 별도 감정 대시보드의 미리보기와 통계로 확인할 수 있다.
- 커뮤니티 감정 결과는 회사·공고 순위 및 기업회원 통계와 섞이지 않는다.
- 실제 공고와 가상 공고가 DB·API·UI에서 명확히 구분된다.
- AI 서버 장애 시 리뷰와 게시판의 핵심 기능은 계속 동작한다.
- 테스트, 프론트 빌드, Docker 검증 결과가 문서에 남는다.
