# 모의면접·실전면접 모드 개편 설계

## 목표

모의면접 시작 화면을 `모의면접`과 `실전면접`의 세그먼트형 라디오 선택으로 개편한다. 무료 모의면접은 저장된 질문 코퍼스를 사용하고, 구독자 전용 실전면접은 Gemini와 회원 스펙·채용공고 RAG를 사용한다. 두 모드는 기존 STT, TTS, MediaPipe 얼굴 분석, 질문 스킵, 세션 종합 리포트 흐름을 공통으로 재사용한다.

## 사용자 흐름

### 첫 화면

- 첨부된 로그인 화면처럼 `모의면접 / 실전면접`을 한 줄 세그먼트형 라디오로 표시한다.
- 키보드와 스크린리더에서 실제 라디오 그룹으로 인식되도록 구현한다.
- 모드를 고른 뒤 해당 모드에 필요한 설정만 단계적으로 표시한다.

### 무료 모의면접

- 모든 로그인 회원이 이용할 수 있다.
- 회원 경력 프로필의 목표 직무만 자동으로 불러온다.
- 목표 직무가 있으면 기본 선택값으로 표시하며 사용자가 다른 직무로 바꿀 수 있다.
- 목표 직무가 없으면 백엔드, 프론트엔드, 풀스택, 모바일, 데이터·AI·기타 중 하나를 선택해야 시작할 수 있다.
- 프로젝트, 기술, 자격증, 자기소개서 등 나머지 회원 스펙은 무료 질문 생성에 사용하지 않는다.
- 질문 유형은 `종합 / 인성 / 역량 / 직무` 라디오로 선택한다.
- 질문 수는 `− [숫자 입력] +` 컨트롤로 정하며 최소 2개, 최대 5개다. 입력창에는 숫자를 직접 입력할 수 있고 범위를 벗어난 값은 2~5로 보정한다.
- “최대 5개까지 선택할 수 있어요” 안내를 컨트롤 가까이에 표시한다.
- 첫 질문은 자기소개로 고정하고 전체 질문 수에 포함한다.
- 나머지 질문은 AI Hub 기반 로컬 질문 코퍼스에서 선택한다. Gemini 등 유료 생성 API를 호출하지 않는다.
- `종합`은 인성·역량·직무 카테고리를 순환하고, 특정 유형은 그 유형의 카테고리만 사용한다.
- 직무 분야는 직무 질문에 강하게 적용하고, 인성 질문에는 억지로 기술 맥락을 섞지 않는다.
- 이미 선택된 질문을 `exclude`로 전달하여 중복을 막는다.

### 구독자 전용 실전면접

- 비구독자가 실전면접을 선택하면 설정 화면 대신 구독 회원 전용 서비스 안내 모달을 표시한다.
- 모달의 `구독하러 가기` 버튼은 구독 섹션이 있는 `/account` 페이지로 이동한다.
- 구독자는 질문 근거를 `스펙만 / 스펙+회사 / 회사` 중 하나로 선택한다.
- `스펙만` 또는 `스펙+회사`에서 사용할 스펙이 부족하면 안내를 표시하고 `스펙 입력하기` 버튼으로 `/capability?tool=profile`에 이동한다.
- `회사` 또는 `스펙+회사`에서는 기존 채용공고 검색 API를 이용해 공고 하나를 선택해야 한다.
- 질문 수는 `− [숫자 입력] +` 컨트롤로 정하며 최소 5개, 최대 10개다.
- 첫 질문은 자기소개로 고정한다.
- 마지막 질문은 입사 후 포부로 고정한다. 회사가 선택된 경우 회사명을 포함하고, 스펙만 선택한 경우 범용 입사 후 포부 문구를 쓴다.
- 전체 질문이 5~7개면 행동 질문을 1개, 8~10개면 행동 질문을 2개 배정한다.
- 행동 질문은 협업, 갈등 조정, 문제 해결 등의 범주에서 Gemini가 생성한다. 확인된 스펙이나 공고 맥락이 있으면 자연스럽게 참고하되 존재하지 않는 경험이나 회사 정보를 만들지 않는다.
- 나머지 중간 질문은 맞춤 RAG 질문으로 채운다.
  - 스펙만: 역량, 프로젝트, 기술, 자기소개서 근거
  - 회사: 채용공고 요구사항과 직무 근거
  - 스펙+회사: 보유 역량과 공고 요구사항의 일치점 및 확인되지 않은 역량을 대조
- 질문마다 프로젝트 기여도, 기술 선택 이유, 장애 해결, 요구역량 검증 등 서로 다른 관점을 부여한다.
- 정규화한 질문 텍스트와 `exclude` 목록으로 중복을 차단한다.
- Gemini 생성 실패나 중복 발생 시 같은 유형의 코퍼스 질문으로 대체한다.

## LLM과 TTS 정책

- 실전면접 질문 생성 프롬프트에는 전문 채용 면접관 역할을 부여한다.
- 심리적 압박, 공격, 가스라이팅을 유도하는 지시는 사용하지 않는다.
- 질문은 TTS로 자연스럽게 읽을 수 있는 짧고 명확한 한국어 구어체 한 문장으로 생성한다.
- 제공된 근거에 없는 사용자 경험, 회사 문화, 채용 조건을 생성하지 않는다.
- 모의면접과 실전면접 모두 기존 Google Cloud TTS 음성 네 가지를 사용자가 선택할 수 있다.
- TTS API 실패 시 기존 브라우저 SpeechSynthesis 폴백을 유지한다.

## 공통 면접 진행

- 카메라·마이크 모드와 채팅 모드를 모두 유지한다.
- 음성 답변은 MediaRecorder로 녹음한 뒤 STT와 음성 지표 분석을 수행한다.
- 얼굴 영상은 서버로 전송하지 않고 브라우저의 MediaPipe로 눈 깜빡임, 고개 방향, 카메라 응시, 화면 중앙 유지 지표를 계산한다.
- 질문 사이 카운트다운과 휴식, TTS 낭독, 녹음 종료 꼬리 구간 보존 로직을 유지한다.
- 모든 질문에서 `질문 건너뛰기`를 제공한다. 건너뛴 질문은 명시적인 답변 없음 문구로 세션에 기록하고 다음 질문으로 이동한다.
- 세션 종료 후 우선 질문별 STT·음성·얼굴 지표를 표시한다.
- 사용자가 `AI 분석 보기`를 누르면 전체 답변을 Gemini 한 번으로 평가한다.
- 건너뛴 질문은 종합 평가에서 답변하지 않은 항목으로 해석하도록 프롬프트에 명시한다.
- 평가 성공 시 기존 Spring API를 통해 타임라인에 저장한다.

## MediaPipe 비언어 행동 분석

- 카메라의 목적은 감정이나 심리 상태 판정이 아니라 화상면접에서 관찰 가능한 행동을 코칭하는 것이다.
- 기기와 사용자의 자연스러운 정면 자세 차이를 줄이기 위해 기기 점검 단계에서 2~3초간 기준 자세를 보정한다.
- 기존 코끝의 2D 이동량만으로 만든 고개 움직임 값은 보조 지표로 격하한다.
- MediaPipe 얼굴 변환 행렬을 활성화해 기준 자세 대비 고개의 좌우·상하 회전과 움직임 안정성을 계산한다.
- 홍채의 눈 안 상대 위치와 고개 방향을 함께 사용해 카메라 정면 응시 비율을 근사한다. 가로 홍채 위치만으로 시선을 단정하지 않는다.
- 얼굴 윤곽의 중심과 크기를 사용해 답변 중 얼굴이 권장 화면 영역 안에 유지된 비율을 계산한다.
- 눈 깜빡임은 blendshape, 시작·종료 히스테리시스, 최소 간격 방식의 기존 계산을 유지한다.
- 전체 녹화 프레임 대비 얼굴이 정상 인식된 프레임 비율과 유효 시선 샘플 수를 바탕으로 분석 신뢰도를 `충분 / 참고 / 부족`으로 분류한다.
- 답변 시간이 너무 짧거나 유효 프레임이 부족하면 수치를 평가 근거로 사용하지 않고 데이터 부족 안내를 표시한다.
- 종합 리포트 응답에 `nonverbal_feedback`을 추가해 비언어적 행동 리뷰 한 문단을 별도 섹션으로 표시한다.
- 비언어 리뷰는 고개 방향 안정성, 카메라 응시, 화면 중앙 유지, 깜빡임의 관찰 가능한 경향과 실행 가능한 연습 조언만 포함한다.
- 긴장, 자신감, 성격, 진실성, 감정 상태를 카메라 지표로 추정하거나 단정하지 않는다.
- 카메라를 사용하지 않았거나 신뢰도가 부족하면 `nonverbal_feedback`은 null로 반환하고 UI에 분석 데이터 부족 안내를 표시한다.

## 코드 구조

- 기존 `MockInterviewPage`의 미디어·세션 진행 파이프라인은 유지한다.
- 모드별 설정 UI를 별도 컴포넌트로 분리한다.
- 숫자 입력과 증감 버튼은 재사용 가능한 `QuestionCountControl`로 분리한다.
- 무료 및 실전 질문 슬롯 계산은 순수 함수로 분리해 UI 없이 테스트할 수 있게 한다.
- 프론트 API 요청에는 질문 생성 모드, 질문 근거 유형, 회원 ID, 공고 ID, 카테고리, 관점, 제외 질문을 명시적으로 전달한다.
- AI 서버는 무료 코퍼스 경로와 유료 Gemini/RAG 경로를 서버에서도 분리해 프론트 값만으로 무료 요청이 Gemini를 호출하지 않도록 한다.
- 기존 단일 질문 평가 API는 호환성을 위해 유지하고, 실제 세션은 종합 평가 API를 사용한다.
- MediaPipe 프레임 샘플, 기준 자세와 세션 집계 결과의 타입을 분리해 원시 좌표가 AI 서버나 Spring 백엔드로 전달되지 않도록 한다.
- 세션 종합 평가 응답과 타임라인 질문 기록에 비언어 리뷰와 집계 지표를 호환 가능한 선택 필드로 추가한다.

## 오류 및 경계 처리

- 구독 상태 확인 중에는 실전면접 시작을 활성화하지 않는다.
- 목표 직무, 스펙 또는 회사 등 선택한 모드의 필수 데이터가 없으면 시작 버튼 대신 해당 입력·선택 행동을 안내한다.
- 숫자 입력이 비었거나 숫자가 아니면 포커스를 벗어날 때 해당 모드의 최솟값으로 보정한다.
- 질문 생성 일부가 실패해도 코퍼스 폴백으로 전체 질문 수를 채운다.
- 질문을 충분히 확보하지 못한 경우 중복 질문을 넣지 않고 사용자에게 다시 시도할 수 있는 오류 화면을 표시한다.
- STT, TTS, 카메라, MediaPipe 실패에 대한 기존 폴백과 안내를 보존한다.
- 타임라인 저장 실패는 종합 리포트 표시를 막지 않는다.

## 테스트 기준

- 무료 질문 수가 항상 2~5이고 첫 질문이 자기소개인지 검증한다.
- 실전 질문 수가 항상 5~10이며 첫 질문과 마지막 질문이 고정 문구인지 검증한다.
- 회사가 있으면 마지막 질문에 회사명이 포함되는지 검증한다.
- 5~7개에서 행동 질문 1개, 8~10개에서 2개가 배정되는지 검증한다.
- 스펙만, 스펙+회사, 회사 요청이 올바른 RAG 문맥을 사용하는지 AI 서버 단위 테스트로 검증한다.
- 무료 요청이 Gemini 호출 없이 코퍼스만 사용하는지 검증한다.
- 중복·생성 실패 시 코퍼스 폴백이 작동하는지 검증한다.
- 질문 수 입력의 직접 입력, 증감, 최솟값·최댓값 보정을 컴포넌트 테스트로 검증한다.
- 비구독 모달의 구독 이동과 스펙 부족 안내의 스펙 입력 이동을 검증한다.
- 음성, 채팅, 질문 스킵이 모두 마지막 종합 리포트까지 도달하는지 통합 흐름을 검증한다.
- 기준 자세 보정 전후의 동일한 얼굴 회전이 상대값으로 계산되는지 검증한다.
- 얼굴 회전, 홍채 위치, 얼굴 중심·크기 입력으로 응시 및 중앙 유지 지표가 기대 범위에 드는지 검증한다.
- 유효 프레임 비율과 답변 길이에 따라 분석 신뢰도가 올바르게 분류되는지 검증한다.
- 신뢰도가 부족하면 `nonverbal_feedback`이 생성되지 않고, 충분하면 관찰 가능한 지표만 포함하도록 평가 프롬프트와 응답 파싱을 검증한다.

## 범위 제외

- 결제 상품이나 가격 정책 변경
- 새로운 TTS 공급자 추가 또는 음성 감정 합성
- 얼굴 영상 서버 저장
- 카메라를 이용한 감정·긴장·자신감·진실성 판정
- 압박면접·공격적 면접관 모드
- 기존 타임라인 스키마의 대규모 변경
